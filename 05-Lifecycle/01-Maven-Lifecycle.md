# Maven Build Lifecycle

The Maven Build Lifecycle is a sequence of predefined phases that Maven follows to build and manage a project.

A lifecycle consists of multiple phases, and each phase performs a specific task.

---

## Main Maven Lifecycle

The most commonly used lifecycle is the `default` lifecycle.

Important phases include:

    validate
    compile
    test
    package
    verify
    install
    deploy

The general flow is:

    validate
        ↓
    compile
        ↓
    test
        ↓
    package
        ↓
    verify
        ↓
    install
        ↓
    deploy

---

# Important Lifecycle Phases

### 1. `validate`

Checks whether the project is correctly configured and ready for the build.

### 2. `compile`

Compiles the main Java source code.

Example:

    mvn compile

Compiled classes are placed in:

    target/classes/

### 3. `test`

Compiles and runs the tests.

Example:

    mvn test

Test reports are generated under:

    target/surefire-reports/

### 4. `package`

Packages the compiled application into an artifact such as a JAR or WAR.

Example:

    mvn package

Our project generated:

    target/maven-demo-1.0-SNAPSHOT.jar

### 5. `verify`

Performs additional checks to verify that the project meets quality requirements.

### 6. `install`

Installs the generated artifact into the local Maven repository.

Example:

    mvn install

The artifact is stored under:

    ~/.m2/repository/

### 7. `deploy`

Deploys the artifact to a remote Maven repository.

Example:

    mvn deploy

---

# Important Concept: Phases Run in Order

When you execute a later phase, Maven also executes the earlier phases in that lifecycle.

For example:

    mvn package

runs the required phases before `package`:

    validate
       ↓
    compile
       ↓
    test
       ↓
    package

Similarly:

    mvn install

runs the required earlier phases before `install`.

---

# Lifecycle Phase vs Plugin Goal

A lifecycle phase and a plugin goal are not the same.

Example lifecycle phase:

    compile

Example plugin goal:

    compiler:compile

The lifecycle phase determines **when** a task occurs, while the plugin goal performs the actual task.

Relationship:

    Lifecycle Phase
          ↓
    Plugin Goal
          ↓
    Actual Task

---

# Three Maven Lifecycles

Maven has three built-in lifecycles:

1. `default` — builds and deploys the project.
2. `clean` — cleans previous build output.
3. `site` — generates project documentation and reports.

---

# Clean Lifecycle

The Clean Lifecycle removes files generated by previous builds.

The main phase is:

    clean

Command:

    mvn clean

It normally removes:

    target/

We used this command in our project and Maven deleted the `target` directory.

---

# Site Lifecycle

The Site Lifecycle is used to generate project documentation and reports.

The main phase is:

    site

It is less commonly used in basic Maven projects.

---

# Key Points

- A Maven lifecycle is a sequence of predefined build phases.
- The `default` lifecycle is used for building and deploying projects.
- Common phases are `validate`, `compile`, `test`, `package`, `verify`, `install`, and `deploy`.
- Running a later phase also runs the required earlier phases.
- `clean` belongs to the Clean Lifecycle.
- `site` belongs to the Site Lifecycle.
- Lifecycle phases use plugin goals to perform actual tasks.
- A lifecycle phase and a plugin goal are different concepts.

# Interview Questions

### What is the Maven Build Lifecycle?

It is a predefined sequence of phases that Maven follows to build and manage a project.

### What happens when you run `mvn package`?

Maven executes the required earlier phases and then packages the project into an artifact such as a JAR or WAR.

### What happens when you run `mvn install`?

Maven builds the project through the required phases and installs the generated artifact into the local Maven repository.

### What are the three Maven lifecycles?

- Default
- Clean
- Site

### Does `mvn package` run the `compile` and `test` phases?

Yes. Maven executes the required earlier phases before reaching `package`.
